# Public HTTPS deployment

This guide is an end-to-end example for a small Linux host. It keeps the MCP
server on loopback and lets **Caddy** terminate TLS, obtain a Let's Encrypt
certificate, and renew it automatically.

For a quick local setup, use [Deployment](DEPLOYMENT.md#local-http). For a
reverse proxy you already operate, see
[Reverse proxy and TLS](DEPLOYMENT.md#reverse-proxy-and-tls).

## What you need

- A Linux host with `systemd`, Python 3.11 or newer, and `python3-venv`.
- A domain such as `mcp.example.com` with an `A`/`AAAA` record pointing at the
  host.
- Inbound TCP 80 and 443 reachable from the internet so Caddy can complete the
  ACME challenge and serve HTTPS.
- `sudo` access.
- A bearer token generated by `stpt-mcp token`.

The MCP port itself does **not** need to be public. Caddy connects to it over
loopback.

## 1. Create the service account

```bash
sudo useradd --system --home /opt/stpt-mcp --shell /usr/sbin/nologin stpt
sudo mkdir -p /opt/stpt-mcp
sudo chown stpt:stpt /opt/stpt-mcp
```

## 2. Install the server

Install the release wheel:

```bash
sudo -u stpt python3 -m venv /opt/stpt-mcp/.venv
sudo -u stpt /opt/stpt-mcp/.venv/bin/pip install --upgrade pip
sudo -u stpt /opt/stpt-mcp/.venv/bin/pip install \
  "https://github.com/vladirocox/stpt-mcp/releases/download/v0.2.0/stpt_mcp-0.2.0-py3-none-any.whl"
```

Or install the current source checkout:

```bash
sudo -u stpt git clone --depth 1 \
  https://github.com/vladirocox/stpt-mcp.git /opt/stpt-mcp/src
sudo -u stpt /opt/stpt-mcp/.venv/bin/pip install /opt/stpt-mcp/src
```

## 3. Generate the bearer token

```bash
TOKEN=$(sudo -u stpt /opt/stpt-mcp/.venv/bin/stpt-mcp token)
sudo install -m 600 -o root -g root /dev/null /etc/stpt-mcp.env
printf 'STPT_MCP_AUTH_TOKEN=%s\n' "$TOKEN" | sudo tee /etc/stpt-mcp.env >/dev/null
unset TOKEN
```

The token is stored in a root-only environment file. Keep it out of git, shell
history, URLs, and logs.

## 4. Install the systemd unit

Download the example unit for the release and replace `mcp.example.com` with
your hostname:

```bash
sudo curl -fsSL \
  https://raw.githubusercontent.com/vladirocox/stpt-mcp/v0.2.0/deploy/stpt-mcp.service.example \
  -o /etc/systemd/system/stpt-mcp.service
sudoedit /etc/systemd/system/stpt-mcp.service
```

The full unit is also shown in
[`deploy/stpt-mcp.service.example`](../deploy/stpt-mcp.service.example).

Start it:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now stpt-mcp
sudo systemctl status stpt-mcp --no-pager
```

Check that it is loopback-only:

```bash
curl -fsS http://127.0.0.1:8000/healthz
ss -ltnp | grep ':8000'
```

## 5. Configure Caddy

Install Caddy using your distribution's instructions, then add this block to
your Caddyfile. If Caddy already serves other sites, merge this block instead of
replacing the file:

```caddyfile
mcp.example.com {
    reverse_proxy 127.0.0.1:8000 {
        # Streamable HTTP can keep responses open; do not buffer them.
        flush_interval -1
    }
}
```

A copy is in
[`deploy/Caddyfile.example`](../deploy/Caddyfile.example).

Validate and reload:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy obtains and renews the certificate automatically for a normal hostname on
ports 80/443.

### Caddy in Docker

If Caddy runs in a container, it cannot reach the host's `127.0.0.1`. Use the
host gateway and make the MCP listener reachable from that network:

```yaml
services:
  caddy:
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

```caddyfile
mcp.example.com {
    reverse_proxy host.docker.internal:8000 {
        flush_interval -1
    }
}
```

Set `STPT_MCP_HOST=0.0.0.0` and keep the MCP port blocked at the firewall, or
bind it to the Docker bridge address. Do not publish the MCP port directly.

### Non-standard HTTPS port

If you must use a port such as 9000 and already have a certificate, Caddy can
load it explicitly:

```caddyfile
https://mcp.example.com:9000 {
    tls /etc/letsencrypt/live/mcp.example.com/fullchain.pem /etc/letsencrypt/live/mcp.example.com/privkey.pem
    reverse_proxy 127.0.0.1:8000 {
        flush_interval -1
    }
}
```

Add `:9000` to the server allowlists:

```text
STPT_MCP_ALLOWED_HOSTS=mcp.example.com:9000
STPT_MCP_ALLOWED_ORIGINS=https://mcp.example.com:9000
```

Caddy does not renew a manually loaded certificate. Keep the existing renewal
process and reload Caddy after the certificate changes.

### Cloud clients and port 443

Some hosted clients connect from their own cloud infrastructure, not from your
browser, and only allow the standard HTTPS port 443. Claude's custom connector
backend is one example: a URL such as `https://mcp.example.com:9000/mcp` can fail
with "Couldn't reach this address" even when `curl` works from your network.

If you already serve a site on 443, add a path route before the catch-all
redirect:

```caddyfile
example.com {
    handle /mcp* {
        reverse_proxy 127.0.0.1:8000 {
            flush_interval -1
        }
    }

    handle {
        redir https://example.net permanent
    }
}
```

Use `https://example.com/mcp` in the client. Keep the Host allowlist entry as
`example.com`; do not add `:443` unless the proxy explicitly forwards it.
Claude's connector dialog can send a static bearer token through **Request
headers**:

```text
authorization: Bearer <token>
```

Mark the header as required. If the dialog only offers OAuth, the server needs an
OAuth layer; this project currently implements bearer authentication.

## 6. Firewall

Allow only the ports Caddy needs:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# Only for the non-standard-port example:
# sudo ufw allow 9000/tcp
```

Do not allow the internal MCP port (`8000` in this example).

## 7. Verify

Health:

```bash
curl -fsS https://mcp.example.com/healthz
```

Expected:

```json
{"status":"ok","service":"stpt-mcp","version":"0.2.0"}
```

Authentication:

```bash
# Without a token: 401
curl -sS -o /dev/null -w '%{http_code}\n' \
  -X POST https://mcp.example.com/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

# With the token: 200
TOKEN=$(sudo sed -n 's/^STPT_MCP_AUTH_TOKEN=//p' /etc/stpt-mcp.env)
curl -sS -o /dev/null -w '%{http_code}\n' \
  -X POST https://mcp.example.com/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
```

Client configuration:

```json
{
  "mcpServers": {
    "stpt": {
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer replace-with-your-token"
      }
    }
  }
}
```

A copy is in
[`examples/https-client.json`](../examples/https-client.json). Client
configuration formats vary. Put the token in the HTTP `Authorization` header,
never in the URL or query string.

## 8. Certificate renewal

- Caddy-managed certificates on ports 80/443 renew automatically.
- Manually mounted certificates are not renewed by Caddy. Confirm the existing
  ACME client renews them and reload Caddy after renewal.
- Check the expiry and the served chain:

```bash
echo | openssl s_client -connect mcp.example.com:443 -servername mcp.example.com 2>/dev/null \
  | openssl x509 -noout -issuer -dates -ext subjectAltName
```

## 9. Operations and security checklist

- [ ] Keep the MCP listener on loopback or a private network.
- [ ] Expose only the Caddy HTTPS port.
- [ ] Store the token in a root-only file, not in the unit or repository.
- [ ] Send the token in the `Authorization` header.
- [ ] Keep `flush_interval -1` for Streamable HTTP streaming.
- [ ] Add the exact public host (including the port if forwarded) to
      `STPT_MCP_ALLOWED_HOSTS`.
- [ ] Do not enable permissive CORS unless a browser client needs it.
- [ ] Keep the OS, Caddy, and the Python package updated.
- [ ] Watch `journalctl -u stpt-mcp` and Caddy's logs after changes.
- [ ] Test `/healthz`, an unauthenticated `401`, and an authenticated MCP call
      after every upgrade.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| `421 Invalid Host` | The `Host` header is not in `STPT_MCP_ALLOWED_HOSTS`; include the port if the proxy forwards it. |
| `401 Unauthorized` | The client is missing `Authorization: Bearer <token>`, or the token differs from `/etc/stpt-mcp.env`. |
| `502 Bad Gateway` | Caddy cannot reach the MCP listener; check `ss -ltnp`, `STPT_MCP_HOST`, and the Docker gateway address. |
| Streaming stalls | Set `flush_interval -1` and disable proxy buffering. |
| Certificate error | Check DNS, ports 80/443, and `caddy validate`; for a manual certificate, check its expiry and chain. |

## Removal

For a standalone host, stop the service and remove the files:

```bash
sudo systemctl disable --now stpt-mcp
sudo rm -f /etc/systemd/system/stpt-mcp.service
sudo rm -f /etc/stpt-mcp.env
sudo rm -rf /opt/stpt-mcp
sudo systemctl daemon-reload
```

Remove the Caddy site block and reload Caddy. If the host uses a router port
forward, remove that rule too.
